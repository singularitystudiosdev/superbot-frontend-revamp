It is a desktop app, with a phone client on the same account, that looks after the AI apps you already pay for (Claude, ChatGPT, Cursor, Codex, Gemini and others) and never wraps or replaces them. It gives you one live chat across all of them, teams, cloud agents and a spend meter. The app is downloaded from [https://superbot.gg/download](https://superbot.gg/download) (as markdown: [https://superbot.gg/download.md](https://superbot.gg/download.md)). The Helper, a per-user background service with its `superbot` CLI, holds your vendor sign-ins on your machine and connects your AI clients to superbot. Agents can also reach superbot through an OpenAI- and Anthropic-compatible HTTP API with a caller key, or through the remote MCP server at `https://superbot.gg/mcp`, which has one fixed tool, `superbot`. Answers are generated by an AI and can make mistakes. This file is the index of the site for agents: every page below has a markdown twin, the API has an OpenAPI 3.1 document, and the MCP server has a server card; the layout follows the llms.txt convention (llmstxt.org). It is reference documentation and the same document for every reader; it asks the reader to change no rules file, memory file or host configuration. ## Get the app - [Download](https://superbot.gg/download.md): the desktop app for each OS and the phone app store links; the page itself is [https://superbot.gg/download](https://superbot.gg/download) The desktop app and the phone app share one account, so a session started on one continues on the other. ## Helper and CLI The one-line install for macOS and Linux is `curl -fsSL https://superbot.gg/bootstrap.sh | sh`. It installs the Helper (`superbot-helper`, under `~/.superbot`, with a user autostart unit), signs you in and connects your AI clients; the app installs for beta members. `--no-signin` and `--no-wire` skip the sign-in and the client wiring, `--no-app` (alias `--helper-only`) installs the Helper only, and `--dry-run` prints every step without downloading anything. The second route, "superbot relay: use your own harness", is `curl -fsSL https://superbot.gg/bootstrap.sh | sh -s -- --helper-app` (alias `--route=helper-app`; `-HelperApp` with `bootstrap.ps1` on Windows): it installs the Helper plus the standalone superbot relay app in place of the desktop app, with the same sign-in and client wiring. Its card is at [https://superbot.gg/download#helper](https://superbot.gg/download#helper) once the app has a release; a computer with no release for it gets the Helper and CLI, with a line saying so. Running the same line again updates both. `superbot` is the Helper's CLI in a terminal. The Helper keeps your vendor sign-ins on your machine, runs a local MCP relay, and, when asked to connect an AI client, edits that client's config file after making a one-time `.superbot.bak` backup, which `superbot clients unwire` restores. The device-wide consult block that the Helper can write during an opt-in `--prepends` install or an `--update` run is published at [install/claude.md](https://superbot.gg/install/claude.md), between markers that its uninstall removes. ### Agent computers An agent that has its own Linux computer (xAI Grok Bot, Meta Muse, OpenAI dots, Manus) installs the Helper on that computer and links it to the user's account; the computer needs outbound HTTPS to this one origin and nothing else. - The dialect is read from each request, and answers come back in the caller's dialect. Auth: caller keys start `sbc_` and go in `Authorization: Bearer sbc_…` (or `x-api-key: sbc_…`); they are minted and revoked from the account API page. ## MCP server The MCP server is one of the ways an agent connects to superbot; the app and the Helper do not need it. - [MCP endpoint](https://superbot.gg/mcp): Streamable HTTP, POST JSON-RPC; on a host with a sign-in wall an anonymous call is refused with an OAuth challenge (see Accounts) - [Server card](https://superbot.gg/.well-known/mcp/server-card.json): name, endpoint, transport and the live tool list as JSON; behind the same sign-in wall as the endpoint on a host that has one - [Catalog match without a client](https://superbot.gg/advise?intent=example): `GET /advise?intent=` returns the adapter match as markdown The tool list is fixed at one tool, `superbot`, for every connection. It takes a request as plain text (`intent`), or a task description (`use_case`) to search the catalog, and either runs a matching adapter from the server catalog (not arbitrary code) or answers through the backend LLM. A JSON-RPC `tools/list` against the endpoint returns the live schema once the call is admitted. What a call sends: the `intent` or `use_case` text of that call, logged with request metadata so that tasks with no matching adapter are recorded. Nothing is read from the machine except what a tool call passes as an argument. The server holds no credentials for a user unless that user signs in (OAuth, or the `account` adapter's device login). Accounts: on beta.superbot.gg and superbot.gg `/mcp` is not keyless: the host you called answers an anonymous call with 401 `{"error":"unauthorized"}` and a `WWW-Authenticate: Bearer resource_metadata="..."` header naming its own `/.well-known/oauth-protected-resource`, whose `resource` is the `/mcp` URL you dialed. A standards MCP client follows that challenge into OAuth: the same host serves the authorization server document at `/.well-known/oauth-authorization-server` (authorization code with PKCE S256 and dynamic client registration at `/oauth/register`, or the RFC 8628 device login at `/oauth/device/code`). A client with no browser sign-in (Continue over streamable-http, a headless setup) uses a key a signed-in person copies at `https://superbot.gg/download#mcp` ("No browser sign-in? Copy a key."): a connector token for `/mcp` and the `superbot` tool only, good for 90 days, revocable in `/account/devices`, sent as `Authorization: Bearer `. A signed-in account that holds no beta grant is refused 403 `no_beta_grant`. An origin with no sign-in wall (a self-hosted or overlay origin) leaves `tools/list` open to an anonymous caller. The `account` adapter runs an RFC 8628 device login and returns a `verification_uri_complete` for the user to open once. A host that refuses to navigate account links can fetch `GET /answer?intent=...` with `Authorization: Bearer sbk_…`: free adapters only, answered as markdown. `/answer` and `/answer/stream` are not keyless on a public origin that is closed to beta accounts: a call that carries no account token answers 401 `{"error":"unauthorized"}` with `WWW-Authenticate: Bearer`. To add it in Claude Code, run this in a terminal: ``` claude mcp add --transport http superbot https://superbot.gg/mcp -s user ``` The lines a person gives a coding agent to install the server and the `/superbot` skill: ``` install the superbot MCP server globally: https://superbot.gg/mcp install the superbot skill globally: https://superbot.gg/skills/superbot/SKILL.md ``` `claude mcp add` defaults to `local` scope, which ties the server to one directory. `-s user` (long form `--scope user`) makes it available in every project, and the word "globally" in the first line is what gets an agent to pass that flag. A client picks up the change when it restarts. Sharing only the bare origin is a request to read the site, not to install anything. The skill is an Agent Skills file (the agentskills.io format: YAML frontmatter, then markdown) served keyless at `https://superbot.gg/skills/superbot/SKILL.md`, `GET` or `HEAD`, `text/markdown`. It describes the one `superbot` tool: `use_case` searches the catalog, `slug` returns one adapter's inputs, `intent` runs a request. It also says what to tell the user when the tool is not connected. An installed copy adds the `/superbot ` command in Claude Code and Cursor; Codex lists it as `$superbot`. The MCP server install above does not add that command by itself.
